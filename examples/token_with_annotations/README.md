# NEP-17 Token with NEO Contract Annotations

This example demonstrates how to implement a NEP-17 compatible fungible token contract for the NEO N3 blockchain using the annotation-based approach.

## Contract Features

This token implementation includes:

1. **Standard NEP-17 Methods**:
   - `symbol`: Get the token symbol
   - `decimals`: Get the number of decimals
   - `totalSupply`: Get the total token supply
   - `balanceOf`: Get the balance of an account
   - `transfer`: Transfer tokens between accounts

2. **Additional Token Operations**:
   - `mint`: Create new tokens (owner only)
   - `burn`: Destroy tokens
   - `updateOwner`: Change the contract owner

3. **Event Emission**:
   - `Transfer`: Emitted for all token transfers, including mints and burns

## Annotation Approach

This example uses commented annotations to document the contract structure while providing a working implementation:

```rust
// Contract module with metadata
// #[contract]
// #[contract_author("NEO Rust Team")]
// #[contract_description("NEP-17 Token Example")]
// #[contract_version("0.1.0")]
// #[supported_standards("NEP-17")]
mod token_contract {
    // Event definitions
    // #[event]
    pub struct Transfer {
        // #[index]
        pub from: Option<H160>,
        // #[index]
        pub to: Option<H160>,
        pub amount: u64,
    }
    
    // Contract storage definition
    // #[storage]
    pub struct TokenContract {
        // Storage fields...
    }
    
    impl TokenContract {
        // #[constructor]
        pub fn new(owner: H160, initial_supply: u64) -> Self {
            // Implementation...
        }
        
        // #[safe]
        pub fn balance_of(&self, account: H160) -> u64 {
            // Implementation...
        }
        
        // #[method]
        pub fn transfer(&mut self, from: H160, to: H160, amount: u64, data: Vec<u8>) -> bool {
            // Implementation...
        }
    }
}
```

This approach:
1. **Documents Intent**: Shows how the contract would be structured with full annotation support
2. **Provides Implementation**: Includes working code that can be deployed today
3. **Ensures Future Compatibility**: Makes it easy to migrate to full annotation support when available

## Key Implementation Patterns

### 1. Event Emission

Manual implementation of event emission that will eventually be generated by the `#[event]` macro:

```rust
impl Transfer {
    pub fn emit(from: Option<H160>, to: Option<H160>, amount: u64) {
        let mut event_args = Array::new();
        
        // Handle Option parameters
        match from {
            Some(addr) => event_args.push(Any::from(addr)),
            None => event_args.push(Any::null()),
        }
        
        match to {
            Some(addr) => event_args.push(Any::from(addr)),
            None => event_args.push(Any::null()),
        }
        
        event_args.push(Any::integer(amount as i64));
        
        Runtime::notify(&ByteString::from("Transfer"), &event_args);
    }
}
```

## Security Features

This implementation demonstrates key security best practices:

1. **Access Control**: All sensitive operations are protected with `Runtime::check_witness`
   ```rust
   // Only owner can mint tokens
   let owner = self.owner.get().unwrap_or(None).unwrap_or_default();
   if !Runtime::check_witness(&owner) {
       return false;
   }
   ```

2. **Input Validation**: All method parameters are thoroughly validated
   ```rust
   // Check that amount is positive
   if amount == 0 {
       return false;
   }
   
   // Check from has sufficient balance
   let from_balance = self.balance_of(from);
   if from_balance < amount {
       return false;
   }
   ```

3. **Reentrancy Protection**: State updates occur before external calls
   ```rust
   // Update balances FIRST
   self.balances.set(&from, &new_from_balance).unwrap_or(());
   self.balances.set(&to, &new_to_balance).unwrap_or(());
   
   // THEN make external calls (if any)
   if is_contract(&to) {
       // Calls to external contracts...
   }
   ```

4. **Comprehensive Testing**: Security properties are verified through tests
   ```rust
   #[test]
   fn test_transfer_unauthorized() {
       // Tests that transfers fail without proper authentication
   }
   
   #[test]
   fn test_only_owner_can_mint() {
       // Tests that only the owner can mint new tokens
   }
   ```
