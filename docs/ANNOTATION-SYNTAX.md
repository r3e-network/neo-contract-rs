# Using NEO Contract Annotation Syntax

This guide explains how to use the NEO annotation syntax in your smart contracts, with a focus on the documentation-first approach we've adopted.

## Overview

The Neo Contract Rust framework provides a clean, declarative annotation-based syntax for defining smart contracts. While the full implementation of these annotations is still in progress, you can use them in your code today as comments to document your intent, making your code future-ready.

## Annotation Syntax vs. Implementation

While the annotation syntax appears straightforward, there are two main ways to use it:

1. **Documentation Approach**: Use commented annotations (`// #[annotation]`) to document your contract's structure
2. **Future Implementation**: When full annotation support is available, you'll simply uncomment these annotations

### Example: Commented vs. Future Syntax

```rust
// Documentation Approach (Current)
// #[contract]
// #[contract_author("Your Name")]
mod my_contract {
    // #[event]
    struct Transfer {
        // #[index]
        from: H160,
        to: H160,
        amount: u64,
    }
    
    // Implementation...
}

// Future Implementation
#[contract]
#[contract_author("Your Name")]
mod my_contract {
    #[event]
    struct Transfer {
        #[index]
        from: H160,
        to: H160,
        amount: u64,
    }
    
    // Implementation...
}
```

## Complete Annotation Reference

### Contract Annotations

These annotations apply to the contract module:

| Annotation | Purpose | Example |
|------------|---------|---------|
| `#[contract]` | Marks a module as a Neo contract | `#[contract]` |
| `#[contract_author]` | Specifies the contract author | `#[contract_author("Neo Team")]` |
| `#[contract_description]` | Provides a description | `#[contract_description("Token")]` |
| `#[contract_version]` | Specifies the version | `#[contract_version("1.0.0")]` |
| `#[supported_standards]` | Lists supported standards | `#[supported_standards("NEP-17")]` |

### Event Annotations

These annotations define events for the blockchain:

| Annotation | Purpose | Example |
|------------|---------|---------|
| `#[event]` | Marks a struct as an event | `#[event]` |
| `#[index]` | Marks fields that can be indexed | `#[index]` |

### Storage Annotations

These annotations define contract storage:

| Annotation | Purpose | Example |
|------------|---------|---------|
| `#[storage]` | Marks a struct as contract storage | `#[storage]` |

### Method Annotations

These annotations define contract methods:

| Annotation | Purpose | Example |
|------------|---------|---------|
| `#[constructor]` | Marks the contract constructor | `#[constructor]` |
| `#[method]` | Marks a public method | `#[method]` |
| `#[safe]` | Marks a read-only method | `#[safe]` |
| `#[no_reentrant]` | Prevents reentrancy attacks | `#[no_reentrant]` |

## Design Patterns

### Structure-First Pattern

Define your contract structure with commented annotations first, then implement the functionality:

```rust
// #[contract]
// #[contract_author("Your Name")]
mod token_contract {
    // #[event]
    struct Transfer {
        // #[index]
        from: H160,
        // #[index]
        to: H160,
        amount: u64,
    }
    
    // #[storage]
    struct TokenContract {
        balances: StorageMap<H160, u64>,
        total_supply: Item<u64>,
    }
    
    impl TokenContract {
        // #[constructor]
        fn new(owner: H160, initial_supply: u64) -> Self {
            // Implementation...
        }
        
        // #[method]
        fn transfer(&mut self, from: H160, to: H160, amount: u64) -> bool {
            // Implementation...
        }
        
        // #[safe]
        fn balance_of(&self, address: H160) -> u64 {
            // Implementation...
        }
    }
}
```

### Event Emission Pattern

While the full `#[event]` implementation will eventually generate event emission code automatically, here's how to implement it manually now:

```rust
// #[event]
struct Transfer {
    // #[index]
    from: H160,
    // #[index]
    to: H160,
    amount: u64,
}

// Manual implementation
impl Transfer {
    pub fn emit(from: H160, to: H160, amount: u64) {
        let mut event_args = Array::new();
        event_args.push(Any::from(from));
        event_args.push(Any::from(to));
        event_args.push(Any::integer(amount as i64));
        Runtime::notify(&ByteString::from("Transfer"), &event_args);
    }
}

// Usage:
Transfer::emit(from, to, amount);
```

### Storage Access Pattern

For storage structs, implement accessor methods that will eventually be generated by `#[storage]`:

```rust
// #[storage]
struct TokenContract {
    balances: StorageMap<H160, u64>,
    total_supply: Item<u64>,
}

impl TokenContract {
    pub fn new() -> Self {
        Self {
            balances: StorageMap::new(b"balances"),
            total_supply: Item::new(b"total_supply"),
        }
    }
    
    pub fn get_balance(&self, address: &H160) -> u64 {
        self.balances.get(address).unwrap_or(None).unwrap_or(0)
    }
    
    pub fn set_balance(&mut self, address: &H160, balance: u64) {
        self.balances.set(address, &balance).unwrap_or(());
    }
    
    pub fn get_total_supply(&self) -> u64 {
        self.total_supply.get().unwrap_or(None).unwrap_or(0)
    }
}
```

## Entry Points Pattern

While the `#[contract]` annotation will eventually generate entry points, you need to implement them manually now:

```rust
#[no_mangle]
pub fn deploying() -> bool {
    // Initialize your contract here
    let owner = Runtime::calling_script_hash();
    let contract = token_contract::TokenContract::new();
    // ... initialization code
    true
}

#[no_mangle]
pub fn invoke(operation: String, args: Vec<Any>) -> Any {
    let mut contract = token_contract::TokenContract::new();
    
    match operation.as_str() {
        "transfer" => {
            if args.len() != 3 { return Any::boolean(false); }
            
            let from = if let Some(addr) = args[0].as_h160() { addr.clone() } 
                       else { return Any::boolean(false); };
            let to = if let Some(addr) = args[1].as_h160() { addr.clone() } 
                     else { return Any::boolean(false); };
            let amount = if let Some(val) = args[2].as_i64() { val as u64 } 
                         else { return Any::boolean(false); };
            
            Any::boolean(contract.transfer(from, to, amount))
        },
        "balanceOf" => {
            if args.len() != 1 { return Any::boolean(false); }
            
            let address = if let Some(addr) = args[0].as_h160() { addr.clone() } 
                          else { return Any::boolean(false); };
            
            Any::integer(contract.balance_of(address) as i64)
        },
        // ... handle other operations
        _ => Any::null()
    }
}
```

## Migration Path to Full Annotation Support

When full annotation support becomes available, here's how to migrate your code:

1. **Uncomment the Annotations**: Simply remove the comment markers from your annotations
2. **Remove Manual Event Implementations**: The framework will generate event emission code
3. **Remove Manual Storage Accessors**: The framework will generate storage methods
4. **Remove Manual Entry Points**: The framework will generate entry points
5. **Update Contract Instantiation**: Follow the new patterns for instantiating contracts

## Conclusion

The annotation-based approach provides a clean, declarative way to define your Neo smart contracts in Rust. By using commented annotations today, you're documenting your code's structure and creating a path for easier migration when full annotation support becomes available.
