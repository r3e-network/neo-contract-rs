# NEO Contract Annotation Implementation Roadmap

This document outlines the planned approach for implementing full annotation support in the NEO Contract Rust Framework.

## Current Status

Currently, we use a documentation-first approach with commented annotations. This allows developers to define the structure of their contracts while still implementing the functionality manually.

## Technical Challenges

### 1. Macro Implementation

The current macro system has several issues that need to be addressed:

```rust
// Current issues:
// 1. Duplicate macro definitions
// 2. Namespace conflicts
// 3. Limited code generation capabilities
```

The solution involves:
- Restructuring the macro system to use a single definition source
- Implementing a proper namespace system for macros
- Using procedural macros for complex code generation

### 2. Entry Point Integration

The entry points must be properly connected to the contract methods:

```rust
// Current manual implementation:
#[no_mangle]
pub fn invoke(operation: String, args: Vec<Any>) -> Any {
    // Manual dispatch to contract methods
}

// Future automatic implementation:
// Generated by #[contract] macro based on registered methods
```

### 3. Event Emission

The event system needs to automatically generate emission code:

```rust
// Current manual implementation:
impl Transfer {
    pub fn emit(from: H160, to: H160, amount: u64) {
        let mut event_args = Array::new();
        // Manual parameter construction...
        Runtime::notify(&ByteString::from("Transfer"), &event_args);
    }
}

// Future automatic implementation:
// Generated by #[event] macro with proper parameter handling
```

## Migration Strategy

To ensure a smooth transition for developers using the current documentation-first approach:

1. **Backward Compatibility**: Maintain support for existing manual implementations
2. **Progressive Enhancement**: Enable annotations one at a time, allowing partial adoption
3. **Documentation Updates**: Update guides as annotations become fully functional
4. **Migration Tools**: Develop tools to assist in transitioning from manual to annotation-based code

## Success Criteria

The annotation-based system will be considered successful when:

1. **Completeness**: All planned annotations are fully implemented
2. **Usability**: Developers can create contracts using only annotations
3. **Performance**: Generated code performs as well as manually written code
4. **Reliability**: Annotations produce predictable, correct Neo contract behavior
5. **Adoption**: The annotation approach is used by most Neo contract developers

## Conclusion

This roadmap provides a clear path toward full annotation support while maintaining compatibility with existing code. The documentation-first approach serves as a bridge to the future annotation-based system, allowing developers to structure their code in a clean, declarative way even before all annotations are fully implemented.

Progress on this roadmap will be tracked in the framework's GitHub repository, with regular updates as each milestone is reached.
