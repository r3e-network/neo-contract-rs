# NEO Contract Runtime Documentation

## Contract Entry Points

NEO smart contracts have two main entry points that are required for the contract to work correctly with the NEO VM:

1. **Deploy Entry Point**
2. **Invoke Entry Point**

These entry points are automatically generated by the `#[contract]` macro but can also be implemented manually.

## Deploy Entry Point

The deploy entry point is called when a contract is deployed to the blockchain. It allows the contract to perform initialization tasks.

```rust
#[no_mangle]
pub fn deploying() -> bool {
    // Initialize contract state
    true // Return true to indicate successful deployment
}
```

### Implementation Details

Internally, the `#[contract]` macro generates a WebAssembly export called `_deploy` that calls the user-defined `deploying` function and converts its return value to an integer status code for the NEO VM.

```rust
#[no_mangle]
pub extern "C" fn _deploy(data: *const u8, length: i32) -> i32 {
    // Call the deploying function and convert its return value
    if unsafe { deploying() } {
        1 // Success
    } else {
        0 // Failure
    }
}
```

## Invoke Entry Point

The invoke entry point is called when a contract method is invoked. It receives the method name and arguments.

```rust
#[no_mangle]
pub fn invoke(operation: String, args: Vec<Any>) -> Any {
    match operation.as_str() {
        "transfer" => {
            // Handle transfer operation
            // ...
            Any::boolean(true)
        },
        "balanceOf" => {
            // Handle balanceOf operation
            // ...
            Any::integer(100)
        },
        _ => Any::null() // Unknown operation
    }
}
```

### Implementation Details

Internally, the `#[contract]` macro generates a WebAssembly export called `_invoke` that:
1. Deserializes the operation and arguments from raw data
2. Calls the user-defined `invoke` function
3. Serializes the return value for the NEO VM

```rust
#[no_mangle]
pub extern "C" fn _invoke(operation: *const u8, op_len: i32, args: *const u8, args_len: i32) -> i32 {
    // Deserialize operation and args
    // Call invoke function
    // Serialize return value
    1 // Success
}
```

## Manual Implementation

While the `#[contract]` macro handles these entry points automatically, you can also implement them manually for more control:

```rust
#[no_mangle]
pub extern "C" fn _deploy(data: *const u8, length: i32) -> i32 {
    // Custom deployment logic
    1 // Success
}

#[no_mangle]
pub extern "C" fn _invoke(operation: *const u8, op_len: i32, args: *const u8, args_len: i32) -> i32 {
    // Custom invocation logic
    1 // Success
}
```

## Debugging Entry Points

For testing purposes, the framework provides non-WebAssembly implementations of these entry points that can be used to simulate contract invocation without deploying to the blockchain:

```rust
#[cfg(not(target_arch = "wasm32"))]
pub fn __neo_deploy_entry(data: *const u8, length: i32) -> i32 {
    // Dummy implementation for testing
    1 // Success
}

#[cfg(not(target_arch = "wasm32"))]
pub fn __neo_invoke_entry(operation: *const u8, op_len: i32, args: *const u8, args_len: i32) -> i32 {
    // Dummy implementation for testing
    1 // Success
}
```

These implementations are used by the testing utilities to simulate contract execution.

## Development Considerations

1. **Return Values**: The `deploying` function should return a boolean, and the `invoke` function should return a value of type `Any`.

2. **Error Handling**: Errors should be handled appropriately by returning `false` from `deploying` or the appropriate error value from `invoke`.

3. **Access Control**: Implement proper access control in your contract methods to ensure only authorized users can perform certain operations.

4. **Storage**: Initialize contract storage in the `deploying` function for persistent state.
